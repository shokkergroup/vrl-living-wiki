1The Goal

The Vigilante Racing League (VRL) is a real iRacing NASCAR-style sim league that has raced nearly every Wednesday night since August 2021. Its broadcasts — 2 to 3 hours each with live two-person commentary — live on YouTube across four different broadcaster channels (the league outlived three broadcast partners). One departed broadcaster deleted their uploads, so part of the league's history is lost media.

The project builds a living wiki of that entire history with three promises:

  • Everything indexed to the second. Type a driver's name ("Ricky Whittenburg") and get every race they appear in, every moment they caused, and every time the booth said their name — each one a ▶ button that plays the original YouTube broadcast at that exact second.
  • Zero-maintenance updates. New race nights appear by re-running one script; every derived page (Hot 100, Winner's Circle, rivalries…) recomputes automatically.
  • A product, not a one-off. This is the racing-league prototype of the SHOKKER LORE platform (sister build: The Lapsed Fan podcast wiki). The intent is to sell living wikis to other leagues/series — the league-specific parts are isolated in a "Show Pack" config (assets/show.js) plus data, so standing up a new league is config + pipeline run, not new code.
Secondary goal — a love letter. This is the league owner's own league. The wiki should feel like a fan-made shrine, not a database: wanted posters, a late-night scanner channel, censored-cussing archive, victory-lane frames. Personality is a feature requirement, not decoration.

3Architecture

Two halves, strictly separated: an offline pipeline (Python, runs on the owner's PC) that produces static data files, and a runtime (plain-JS static SPA, no build step, no server logic) that renders them. Compute happens offline; runtime is free to host anywhere. This mirrors the PodWiki playbook: "compute offline, ship static artifacts."

Runtime design decisions

  • No framework, no bundler. One IIFE, hash routing, template strings. Rationale: zero build friction for a solo owner-operator; page views are simple renders of pre-computed data.
  • YouTube IFrame API for playback. Two players: an inline player on race pages and a floating dock player (bottom-right) for playing any moment from any page. __play(videoId, seconds) is the universal entry point — every ▶ in the app routes through it. If the inline player is showing the same video, it seeks; otherwise the dock loads it. Highlight reels extend the dock sequence contract with per-cut source IDs, so continuation broadcasts switch videos at the exact boundary.
  • Transcripts are lazy. 222 eligible transcripts ≈ many MB; each is a separate assets/tr/<id>.js loaded only when needed (race page, deep search). Deep search scans progressively with a progress bar and can be superseded mid-run (generation counter).
  • Everything else loads eagerly (including the dossier data layer). Fine at current scale; see §11 for the split-when-bigger plan.

6The AI Distill System & Cost Economics

The only part of the system that uses AI at scale: one agent reads one race's transcript (transcripts/<id>.txt, typically 100–300 KB) plus its metadata and returns structured JSON, which it also writes to distill/<id>.json (crash-safe: files land as agents finish, so a killed batch keeps its progress).

Distill schema (enforced via structured output)

{
  id, recap (3-5 sentences, facts from tape only),
  winner | null, podium[≤3],
  moments[6-12]: {t seconds, title, summary, kind: wreck|pass|restart|finish|drama|funny|moment,
                  heat 1-5, driverNames[]},
  drivers[]: {name (best-guess proper), spellings[] (caption variants seen)},
  soundbytes[3-8]: {t, quote (verbatim), context, gold 1-5},
  broadcasters[], notes (uncertainties)
}

Batching & the hard rules (learned the hard way)

Incident report: the first attempt fanned out ~200 agents at once (one per race). It burned 3.24M tokens and died against the owner's subscription usage limit having completed only 28 races. The owner's standing rule since: max 3 concurrent agents, batches only with explicit owner approval and a token estimate up front, actual cost reported after. This rule is enforced structurally: gen_workflow.py historically baked only the selected batch's ids into the workflow script, and the workflow ran a chunked loop (WIDTH = 3 with a barrier between chunks) rather than a wide pipeline. Operational status: all 222 eligible sources are now distilled, so this legacy remote batch path is not part of routine local refresh or polish work.

7Zero-Token Techniques

Most of the wiki's intelligence costs nothing. These are the parts worth stealing for any future league:

7.1 The bleep detector (FIRED UP)

YouTube auto-captions censor profanity as a literal [ __ ] marker. Every marker is therefore a timestamped cussing fit, free. Combined with a rage-phrase regex table (retaliation, dumped him, radio screaming, middle finger…), this yields 296 eligible documented anger moments with zero AI.

7.2 Keyword moment radar (auto-moments)

A cue table (the Big One, flips/airborne/catch fence, caution flies, photo finish, green-white-checkered, booth exclamations, N-wide) scans every undistilled race. Hits cluster in 75-second windows; density boosts heat; guards suppress pre-race chatter and mid-race "finish" false alarms (finish cues only count in the last 28% of the tape). During distillation this supplied 434 clearly badged temporary moments. All 222 eligible races now have human-curated distills, so the active fallback set is empty; the miner remains ready for future uploads and its results stay excluded from the curated Hot 100.

7.3 Roster clustering (union-find + guards)

Auto-captions mangle names relentlessly ("Ricky Whittenburg" appears as Wittenberg / Whitenburg / Whitburgh / "Double Nickel Ri"). The provisional roster clusters name strings from all distills by: (1) shared caption spelling variants, (2) fuzzy full-name similarity bucketed by surname initial — both gated by a first-name compatibility check (equal / prefix / ratio ≥ 0.75). That guard exists because caption garble once stitched two different humans together (Chris Goans merged into Jason Gaines via shared "Gones" variants). Additional rules: booth crew (≥3 booth races) are excluded from the driver roster unless they have ≥3 driver races or ever won/podiumed a race (winner protection); roster_overrides.json lets the owner pin the true spelling of any name, beating caption-majority voting (that's how "Chris Gomes" became Chris Goans — the owner's own file names proved the spelling).

7.4 The Mention Machine (n-gram scan)

Every roster name + alias becomes a word-tuple key (1-grams only for distinctive ≥6-char surnames that map to exactly one driver). A single pass over all 222 eligible transcripts does longest-match n-gram lookups per caption line — fast (seconds), no giant regex. Output: per-driver mention counts per race (the Hall's "booth mentions"), and same-line co-mentions become the Shared-Tape Wire (top pair: Anderson–Adamson, 181 shared calls) with clickable tape refs.

7.5 Victory frames (yt-dlp + ffmpeg)

For every known winner: pick a timestamp (victory-lane chapter marker if the broadcast has one → last finish-kind moment +35s → 96.5% of duration), download six seconds of 480p video with yt-dlp --download-sections, extract one frame with ffmpeg (bundled via imageio-ffmpeg), save 640px JPEG. The frames routinely capture the FINAL LAP banner or the results tower with the winner's name+car on screen — authentic broadcast history at zero AI cost. Frame presence never authenticates a result. There are 124 race-night frames total; 87 of the 155 exact-receipt winner sources have a frame, while 68 remain eligible for the resumable backfill.

7.6 Hand-distillation when the tape is explicit

Season 7's finale never made an AI batch, but a grep of the transcript's closing minutes found the literal championship call. The distill JSON was written by hand from those lines (flagged as such in notes). Lesson: for targeted facts, grep-then-read beats spending 100k tokens.

9Known Issues & Limitations (honest list)

  • dataAuto-caption quality bounds everything. Names, quotes and search all inherit caption garble. Whisper re-transcription of the audio would be far cleaner but costs compute for 486 hours of eligible public tape (see §11).
  • dataThe confirmed-start ledger is conservative, not an official entry list. Driver Dossiers now disclose that the current index mixes participant and incidental booth mentions; confirmed starts remain null, but a missed name in an old recap can still undercount a start. The page labels the basis and never inflates the total with mentions.
  • dataRoster clustering is heuristic. Owner overrides now resolve the known Alan/Allen/Jess Vaught identity and Dave/David Mayberry, while winner protection prevents dangerous merges. A full owner pass over roster.json can still catch less-visible cases.
  • dataSeason 9–11 numbering is medium-confidence. Lost tape breaks the anchor chain; TLN-era "Race #1"s are missing. S10 may not have had a separate playoff. Owner review recommended.
  • dataRace distill coverage is complete. All 222 eligible sources meet the 6-12 moment and 3-8 exact-soundbyte targets; future work should deepen reviewed results and entry ledgers, not fabricate extra clips.
  • dataHeat calibration varies by archivist. The new Hot 100 reduces that weakness with iconic-evidence, booth-gold, finish-stakes, and race-context signals, but a human head-to-head normalization of the heat-5 pool would still sharpen the top 20.
  • infraPrivate production is live with a bespoke OG/social card. A custom domain, analytics, SEO prerender (the hash-routed SPA is still mostly invisible to crawlers), and the TLF third-party search widget remain productization opportunities.
  • uxMobile navigation is implemented and contract-tested. The small-screen menu exposes its expanded state, closes after navigation, and is covered by rendered-product tests; representative real-phone visual QA remains useful.
  • dataView counts are a snapshot from fetch time; they drift. Fine for "most watched of all time", stale for recent races.
  • data68 exact-receipt winner sources still lack candidate victory frames. A smaller older set hit age, region, or section-download failures. Continuation uploads are now merged into 219 canonical events with explicit source roles; frame presence remains presentation evidence, never result authentication.
  • productYouTube dependency. If a channel deletes uploads (it happened once), moments break. The pipeline re-scans on update and the Memorial documents gaps, but there's no local archival story (deliberately — rights/size).

  • high valueSemantic search. The TLF sister build already ships quantized embeddings + in-browser cosine (transformers.js) — port it: "that time the spotter said clear and he wasn't" should find the moment without keyword luck. Offline embedding build, static .bin artifact.
  • high valueWhisper re-transcription of top races (or all, locally on GPU over nights): fixes names/quotes at the source; auto-captions remain the fallback.
  • Official entry-list reconciliation. The dossier builder now mines number→driver evidence by season and exposes playable receipts. Importing league entry lists would turn the transcript-derived number history into a fully authoritative registry.
  • Booth diarization (who said it — per-host pages, "Alan vs Adam" quote battles). pyannote locally, zero API.

Content & storytelling

  • high valueStandings reconstruction. Distills capture winners/podiums; full finishing orders often appear in results-tower frames and closing commentary. Even partial points tables per season would unlock "title race" pages and add full points tables and richer title-race context beyond the reviewed title receipts.
  • Story arcs / feud chapters. The Shared-Tape Wire has the data; a cheap synthesis pass could write "the Anderson–Adamson wars" as narrated chapters with tape.
  • Community calibration for the Hot 100. The deterministic memorability model is now live; an owner ballot or lightweight fan voting could supply a human signal without letting recency or popularity erase older archive moments. A yearly "SuperClash Awards" page could reuse it.
  • Start Here onramp for new league members: ten moments in order that explain the league; gateway playlist.
  • Clip factory: auto-cut vertical clips (yt-dlp section + ffmpeg crop + caption burn) for the league's socials — every clip a recruitment backlink.

Platform / productization

  • high valueShow Pack extraction. Formalize what's VRL-specific (show.js, title-filter rules in fetch_meta, cue tables?) into a documented config so league #2 is a form-fill. The per-channel title-filter rules are currently code — they should be config.
  • SEO prerender: generate real HTML pages per race/driver + JSON-LD + sitemap + OG images (the TLF pipeline has build_static.py/build_og.py to port).
  • Perf at scale: split distilled.js per era, IndexedDB-cache transcripts, service worker for offline; matters as the 222-race public archive is fully distilled and if a league has 500+ races.
  • Member layer: Patreon-gated features (After Dark, FIRED UP) as the recurring-revenue story when selling to leagues.
  • Operator console: multi-tenant build dashboard (batch approvals, cost ledger, validation status) — the business backend if this becomes SHOKKER LORE the product.

13Questions for the Reviewer

Q1. Roster identity: is union-find over caption spellings + first-name guard + owner overrides the right architecture, or would you model driver identity differently (e.g. explicit entity store with per-season car numbers as primary keys, captions as evidence)?
Q2. The eligible archive is fully transcribed and distilled. Should technical reboot fragments and failed streams stay only in the internal exclusion report, or receive a public “broadcast archaeology” memorial that explains why they are not counted as races?
Q3. Excitement and Hot 100 calibration: do the current explainable weights (finish drama, lead battle, booth energy, chaos, and curated heat) feel right after watching the top 25? Should owner/fan ballots be blended in as a separate human signal, and if so, how do we prevent recency and popularity bias?
Q4. Architecture: the runtime is a single 1,600-line vanilla-JS file by design (owner-operated, no build step). At what point does that decision break, and what's the lightest migration that preserves "unzip and open"?
Q5. Season 9–11 reconstruction: given lost tape, is there a defensible methodology for numbering (e.g. probabilistic round assignment from dates + track rotation), or should the wiki present those seasons as explicitly "survival-order" and stop implying official rounds?
Q6. Productization: what's missing from the Show Pack boundary before a second league could be onboarded without touching code? (Known gap: per-channel title-filter rules live in fetch_meta.py.)
Q7. Anything in §7 that's fragile in ways not listed in §9? The bleep detector, the n-gram mention scan, and the victory-frame timestamp heuristic have had the least adversarial review.
